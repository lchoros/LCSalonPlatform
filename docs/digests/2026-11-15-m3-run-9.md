## Decisions made
- **A calendar address instead of a Google sync** (ADR 0038): nothing outside the salon is needed, and it works with
  every calendar app. One way only.
- **First name and initial only** in the calendar. Marked Tier 2 because personal data leaves the salon.
- **The next visit is offered, never booked, by the tap** (ADR 0039): the desk still picks the time.
- **The rebook weeks are a setting without a page yet**: 4, 6 and 8 by default.
- **A return never edits the sale** (ADR 0040): it is a new line that points at it, at the price paid.
- **An opened product does not come back to the shelf**: the desk unticks one box.
- **The waitlist is the desk's, not the public's** (ADR 0041). A public form would collect a stranger's phone number
  without the text code a booking has; that is left for the owner.
- **Thin views.** The owner asked whether code in a view is normal. Titles and class names are; calculations,
  addresses and formatting are not. The checkout view is cleaned in #83; 22 other views carry helper code and get
  their own PR when a slot is free.

## What was learned
- A view variable named `page` is a Razor keyword. A migration generated after a failed build is empty; build first.
- Playwright's own HTTP client does not resolve `*.localhost`; it needs the loopback address and a `Host` header.
- Integration and browser tests share one database: a setting an integration test saves is still there for the
  browser test. The browser fixture now resets the rebook weeks with the other settings.
