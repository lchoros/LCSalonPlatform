## What the owner asked for and what was done
- **"Keep the UI more like that."** The admin pages now use the vocabulary of the booking flow: compact buttons
  and fields, panels with the thin border and glow, list cards, a mark under every page title and a line in the
  brand colours on top.
- **The menu shows where you are.** The current area is the dark link.
- **Reports** open with four tiles (taken, visits, no-show rate, not paid) and use two columns on a desk.

## Decisions made
- **Stripe is parked by the owner** ("I do not think we need this now"). Nothing was built. He created a separate
  Stripe sandbox for the day it is needed. What is settled for then: online payment is for the booking deposit
  only, each salon connects its own account, payment happens on Stripe's page and lands on the existing ledger.
  Tier 2 when it comes.
- **`aria-current="true"` on the menu, not "page"** (ADR 0033): the link names an area, not the page.

## Blocked
Nothing.

## What was learned
- Two existing tests failed on the first attempt and both were right. One forbids the word "hidden" on the booking
  page, and an `aria-hidden` element in the layout broke it: the line became the header's background. The other
  reads "no period is chosen" from the absence of `aria-current="page"`: the menu uses "true". Neither test was
  touched.
- The same class string in 28 places is cheap to write and expensive to change. New views use the vocabulary.
