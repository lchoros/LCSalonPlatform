## `main` is red on one job, and why
The `security-scan` job (CodeQL) runs on `main` only. After the merge it reported three findings of
`cs/exposure-of-sensitive-information`, all in log calls that write the message channel. The value is the enum member
`MessageChannel.Email`; CodeQL reads the name as an email address. No address was logged. #70 removes the data flow
instead of suppressing the rule. It cannot be proven on a PR, because the job is skipped there; the proof is the run
on `main` after #70 merges.

## Decisions made (each in its ADR as "owner may veto")
- **Code style (0028).** `using` layout aligned with the nopCommerce standards. Braces stay on every block and
  constants stay PascalCase: neither can be changed by a tool (the Roslyn naming fix refuses to run across a
  solution and does not see Razor), and a hand edit of control flow in 600 files is a poor trade before the pilot.
  The ADR says what each would cost if the owner wants it.
- **Desk bookings (0029).** Every booking gets the client's own link. A desk booking is confirmed by text and email by
  default; one tick box on the reminders settings page switches that off.

## What was learned
- CodeQL only runs on `main`, so a finding arrives after the merge. Log calls must not take a value whose name looks
  like personal data (`Email`, `Phone`), even when it is an enum member.
- `dotnet format` never removes blank lines between `using` groups; flipping the setting only stops it adding them.
- An unticked box posts nothing. Every new tick box on a settings form defaults to "off" for a form that does not
  send it, so tests that post the old field list now switch the new setting off; that is correct and expected.
