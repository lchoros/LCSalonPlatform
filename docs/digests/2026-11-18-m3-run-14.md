## Decisions made
- **"Own payment methods" was read as: the owner names the ways the salon takes money**, and the desk picks them
  wherever money is taken or given back (ADR 0060). It was not read as connecting the salon's own Stripe or PayPal
  account so the system charges cards: that stays parked, as the owner said on 2026-11-15, and the settings page
  says in words that nothing is charged through a method.
- **The line keeps the method's id and its name on that day.** A rename does not rewrite the ledger; the totals
  show one line per method under its latest name.
- **Cash cannot be switched off**, because the cash-up counts the drawer. The other three built-in methods can.
- **A switched-off built-in method is hidden, not refused**; an own method taken out of use is refused.
- **One list for every form.** A tag helper renders the salon's methods, so the nine forms that ask how money
  changed hands cannot drift apart.
- **No existing test was changed.** A built-in method converts to the new choice by itself; the 829 integration
  tests that were there passed before a new one was written.

## What was learned
- `Enum.TryParse` reads "Cash,Voucher" and "3" as values. A form field that names an enum member must be matched
  against the exact names.
- A SQL check that compares with `=` passes when the column is NULL. `IS NOT DISTINCT FROM` says what was meant.
- Never put `git reset --soft`, `git stash` and `ef migrations remove` in one command (run 13): the stash empties
  the tree and the remove then takes the previous feature's migration. Nothing was pushed in that state.
