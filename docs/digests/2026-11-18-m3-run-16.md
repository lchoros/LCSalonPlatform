## Decisions made
- **Next was the price list from a file**, because the plan's one open item that is not blocked is "pilot salon
  onboarding", clients and products already come over from a file, and a price list of a hundred services had to
  be typed one by one. The pilot salon's list in the demo data has guessed times that somebody has to correct.
- **A file updates the services the salon has**, which the product import does not do (ADR 0045 called that
  riskier). The risk is met by the preview: every change is shown as it is and as it will be before anything is
  written, and a file that would do nothing has no confirm button.
- **Only the time, the price and the deposit change.** Not the name, the category, whether a service is in use, or
  who does it. Nothing is ever removed.
- **An empty cell means "leave it as it is"**, so a file with only names and prices is a price rise and nothing
  else.
- **The salon's own file reads back**, in English and Polish, so a yearly price rise is: download, edit in a
  spreadsheet, upload, read the preview, confirm.
- **Decided again at the confirm**, against the services as they are then.
- **Tier 2 by the agent's choice.** No migration and no new table, but one press changes many prices.

## What was learned
- A stacked PR is pointed at `main` by GitHub the moment its base is merged, and can then be merged at once. A
  review that waits for checks must look at the list of PRs again before it is posted.
- A shell heredoc inside a shell heredoc broke the command; a longer edit script is written to a file first.
- "1 rows were left out" reads badly. A sentence with two counts is written so that it is right for any number
  ("Rows left out: 1.").
