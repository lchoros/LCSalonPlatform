## Decisions made
- **Next was the mark on the diary**, which ADR 0065 left out. While a freed time is kept for a waiting client, the
  desk's booking form does not offer it, but the diary showed an empty slot with no reason. A receptionist with a
  client at the counter could not tell why the time would not book.
- **On the day list, above the person's visits**, with the client's name, the service, until when, and the button
  to let it go. It is something to act on, not a visit, so it is not mixed into the visits' time order.
- **On the calendar, on the grid like a visit**, dashed and amber, with the first name only, as the calendar shows
  for visits. A tap opens the day's list.
- **Letting it go from the day goes back to the same day.** The form sends the day, and only a well-formed date is
  put in the address. Anything else goes to the waitlist, as before.
- **A time whose minutes ran out is not marked**, because the booking pages already offer it again. The task that
  passes it on runs every minute.
- **Tier 1**: two screens that only read, and one redirect. The rule for keeping a time is ADR 0065's and unchanged.

## What was learned
- A waiting client is texted at most once a day (ADR 0056). A test that frees a second time for the same client the
  same day gets no offer; a second client has to be waiting.
- Unit tests cannot reach the web project, so a small pure method on a slice's record is tested in the integration
  project beside the page that uses it.
