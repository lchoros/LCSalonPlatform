## Decisions made
- **Next was the diary from a file**, because it is what keeps a salon on its old system: clients, products and the
  price list already come over from a file, the coming months of bookings did not. It is the plan's one open item
  that is not blocked ("pilot salon onboarding").
- **Mapped and attacked before it was coded.** With the owner's ultracode switch on, six readers mapped everything a
  booking touches and what the old systems export, and three reviewers with a judge attacked the design. The map
  showed that booking through the normal path would text every client, refuse most real diaries (outside the rota,
  months ahead, off the quarter hour) and overwrite the agreed prices. The review changed ten things; ADR 0067 marks
  them. The four that mattered most: the reminder gap in the first day (the page now says until when the old system
  must keep reminding, instead of "switch it off today"), the one write (events are queued and saved with the visits,
  so a clash refuses the whole file), a second file (a visit brought over before is never brought over again,
  whatever became of it), and history in the export (counted and dropped, so the size caps apply to the future only).
- **Nothing is created from the file.** Clients, services and people must exist; the page gives the order.
- **Every match fails closed.** A phone on no card is not tried as a name; a family phone with another first name is
  refused; a leaver is never found in a colleague by first name; an unknown status word is not booked.
- **Silent at import, reminded from now on.** A new source, `Import`, is skipped by the confirmation; reminders run
  from the diary as for any visit.
- **No column-mapping step and no presets.** The vendors publish no column lists, so the reader knows many headings in
  both languages and the refusal says which column it missed.

## What was learned
- A race test was first "proved" by swapping in the pattern the review warned about (save per visit, catch the
  clash), and it still passed: EF kept the refused visit in its change tracker and the final save threw again. The
  real guard is that the clash propagates. With exactly that removed (the clash swallowed), the test fails three
  times out of three. Remove the guard itself when proving a test, not a story about it.
- A unique index and a database rule can hide a missing guard; so can EF's retry of what it still tracks.
- An example line of headings that scrolls sideways inside a box is an accessibility fault (axe: "scrollable region
  must have keyboard access"). Let it wrap.
- A nested `@if` inside a Razor code block does not compile; inside code, `if` takes no `@`.
