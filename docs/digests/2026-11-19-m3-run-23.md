## Decisions made
- **Next was the undo of a diary file** (the "undoing a file" line of ADR 0067): the riskiest onboarding moment —
  a wrong file fills the coming weeks and had no way back. v1.0's feature list is otherwise done; what is left is
  pilot onboarding, and this de-risks it.
- **A batch id, not a timestamp**: every commit stamps its visits with one `ImportBatchId` (additive migration).
  Identifying a batch by `CreatedAt` equality works today but is an accident, not a contract.
- **Delete, not cancel**: the point is a diary as if the file had never been read; cancelled ghosts would stay in
  every list. One `ExecuteDelete` that re-checks "still exactly as the file left it" (booked, one history line, no
  money, no products) in the statement itself; the database's `Restrict` rules on money and product rows stand
  behind it, so a racing payment rolls the whole command back.
- **Tier 2**: the feature deletes visits. Label `needs-owner`.

## What was learned
- EF Core cannot translate a grouped projection that news a record while counting a correlated subquery per group;
  two flat queries (group counts, then the filtered counts joined in memory) translate cleanly.
- A guard proof by removal must rebuild the test project, not just the library, or `--no-build` runs the old copy
  (run 21's lesson, applied here on purpose).
